# PaperAgent 项目部署与运行

更新日期：2026-09-30。代码根目录为仓库中的 `PaperAgent-main/`。本文给出 Linux 单机部署方案；本轮实际验证环境是 Windows、Python 3.12.7、Node.js 24.14.0。新 Linux 服务器的安装、模型下载及外部 API 连通性仍需按文末清单验收。

## 1. 组成与前置条件

| 进程 | 作用 | 监听 |
|---|---|---|
| Nginx | 前端静态文件、SPA 路由回退、`/api/` 反向代理 | 80/443 |
| FastAPI | 账号、资料库、问答、翻译、研究、团队等 API | 服务器本机 127.0.0.1:8001 |
| `vector.py` | 轮询待处理 PDF，解析、切分、摘要、写入 Chroma 索引 | 无端口 |
| SQLite / Chroma / PDF | 业务数据、向量索引、论文原件 | 本地磁盘 |

准备 Python 3.12、Node.js 与 npm、Nginx、Git，并为 Python/Node 依赖、模型和 PDF 留出磁盘空间。完整 BGE-M3 与重排模型需要额外数 GB 磁盘和较多内存；容量需按实际并发和论文量压测确定。基础 ONNX 模型位于仓库的 `PaperQuery_Backend/res/onnx_models_v5/`。首次安装离线翻译模型需要网络，或在联网机器下载后单独分发。

DeepSeek API Key 是后端启动的必需配置；Kimi、智谱 GLM 和 OpenAI 为可选配置。`/health/ready` 仅检查模型是否已配置和本地组件是否初始化，不代表云端 API 已通过实际调用。

## 2. 下载与目录

以下示例使用 `/opt/paperagent`；也可用团队自己的绝对路径。API 和 Worker 必须以 **`PaperQuery_Backend` 为工作目录**运行，因为 `.env` 中多个存储路径是相对路径。

```bash
sudo mkdir -p /opt/paperagent
sudo chown -R "$USER":"$USER" /opt/paperagent
git clone https://github.com/ll-206/PaperAgent.git /opt/paperagent
cd /opt/paperagent/PaperAgent-main/PaperQuery_Backend
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirement.txt
mkdir -p res/AcadeAgent res/pdf res/tmppdf res/layer1 res/layer2 res/tasks
```

如服务器没有 `python3.12` 命令，先安装受支持的 Python 3.12 运行时，勿直接用系统自带的未知版本。依赖列表包含离线翻译、BM25 和中文分词。推荐用 `pip check` 核对依赖一致性。

## 3. 后端配置与模型

```bash
cd /opt/paperagent/PaperAgent-main/PaperQuery_Backend
cp .env.example .env
chmod 600 .env
```

编辑 `.env`，至少设置以下字段；密钥只放在服务器 `.env` 或密钥管理器中，不提交到 Git。

```dotenv
DEEPSEEK_API_KEY=填写实际密钥
DEEPSEEK_API_BASE=https://api.deepseek.com
SECRET_KEY=填写随机生成的长字符串
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=1440
DB_PATH=./res/AcadeAgent/database.db
AcadeAgent_DIR=.
PAPER_SAVE_DIR=./res/pdf
TMP_PAPER_SAVE_DIR=./res/tmppdf
CHROMA_LAYER1_DIR=./res/layer1
CHROMA_LAYER2_DIR=./res/layer2
CHROMA_ONNX_CACHE_DIR=./res/onnx_models_v5/all-MiniLM-L6-v2
FRONTEND_ORIGINS=https://paperagent.example.org
MAX_UPLOAD_MB=50
```

可用 `python -c 'import secrets; print(secrets.token_urlsafe(48))'` 生成 `SECRET_KEY`。修改域名时同时修改 `FRONTEND_ORIGINS` 和 Nginx `server_name`。首次启动前不要运行旧 `initdb.py`：它会删除并重建多个业务表。`main.py` 会创建当前 ORM 表并执行现有的小型迁移。

离线英中翻译模型单独安装：

```bash
.venv/bin/python scripts/install_offline_translation.py
```

可选的本地混合检索模型分别放在 `models/bge-m3/` 和 `models/bge-reranker-v2-m3/`。前者须含 `pytorch_model.bin`，后者须含 `model.safetensors`，否则服务继续使用现有 ONNX/Chroma 检索。可在 `.env` 中配置 `BGE_M3_MODEL_PATH`、`RERANKER_MODEL_PATH`；若要显式关闭增强检索，配置 `ENABLE_BGE_RETRIEVAL=false`。这些大型模型未随仓库分发，需要队友单独下载或从经许可的内部存储复制。

## 4. 首次建库与管理员

先短暂启动一次 API 让表和迁移完成，再创建管理员，最后改为守护服务：

```bash
cd /opt/paperagent/PaperAgent-main/PaperQuery_Backend
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8001
# 另一个终端执行下行，按提示输入至少 8 位管理员密码
.venv/bin/python -m scripts.create_admin --username admin --team-name '默认团队'
```

管理员脚本不会覆盖已有账号。现有数据库已有 `admin` 时无需执行；若需要迁移生产数据，请先备份数据库、PDF 和索引。创建完成后停止前台 API，再配置 systemd。不要使用文档里可能出现的演示密码 `123456` 作为服务器密码。

## 5. 前端构建

所有前端请求统一使用 `VITE_API_BASE_URL`。生产部署建议通过 Nginx 同源代理：

```bash
cd /opt/paperagent/PaperAgent-main/PaperQuery_Frontend
cp config/.env.example config/.env.prod
# 确认 VITE_API_BASE_URL=/api，VITE_DEPLOY_BASE_URL=/
npm ci
npm run build
```

`dist/` 是可部署静态目录。构建时环境值会写入 JS，改 API 地址后必须重建。仓库中的 `config/.env.dev` 仅供本地 Vite 开发使用；生产构建不要使用其中的 `127.0.0.1` 地址。

## 6. systemd 与 Nginx 示例

以实际运行账号和路径替换 `paperagent`。建立两个 systemd service，API 先于 Worker 启动；研究任务使用进程内后台任务，当前建议 API **单进程单 worker**，避免任务状态与本地资源重复装载。

`/etc/systemd/system/paperagent-api.service`：

```ini
[Unit]
Description=PaperAgent API
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=paperagent
WorkingDirectory=/opt/paperagent/PaperAgent-main/PaperQuery_Backend
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/paperagent/PaperAgent-main/PaperQuery_Backend/.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8001 --workers 1
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`/etc/systemd/system/paperagent-vector.service`：

```ini
[Unit]
Description=PaperAgent PDF indexing worker
After=paperagent-api.service
Requires=paperagent-api.service

[Service]
Type=simple
User=paperagent
WorkingDirectory=/opt/paperagent/PaperAgent-main/PaperQuery_Backend
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/paperagent/PaperAgent-main/PaperQuery_Backend/.venv/bin/python vector.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`/etc/nginx/sites-available/paperagent` 示例：

```nginx
server {
    listen 80;
    server_name paperagent.example.org;
    root /opt/paperagent/PaperAgent-main/PaperQuery_Frontend/dist;
    index index.html;
    client_max_body_size 50m;

    location /api/ {
        proxy_pass http://127.0.0.1:8001/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;      # SSE 逐段显示
        proxy_read_timeout 3600s; # 长时间问答/研究查询
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

`proxy_pass` 的尾部 `/` 用于将 `/api/login` 转发为后端 `/login`。配置 HTTPS 证书后把 `server_name` 与前端访问域名保持一致。运行 `nginx -t` 后再重载；随后 `systemctl daemon-reload`、`systemctl enable --now paperagent-api paperagent-vector`。

## 7. 验收、运维与故障定位

```bash
curl -fsS http://127.0.0.1:8001/health/live
curl -fsS http://127.0.0.1:8001/health/ready
curl -fsS https://paperagent.example.org/api/health/ready
systemctl status paperagent-api paperagent-vector
journalctl -u paperagent-api -n 100 --no-pager
journalctl -u paperagent-vector -n 100 --no-pager
```

然后在浏览器完成：登录；创建测试知识库；上传一篇测试 PDF 并等待状态为完成；打开阅读器、缩放和翻译；在 Ask 选择该 PDF 问答并核对引用；保存/删除测试笔记；提交一项测试研究并查看任务详情；管理员重命名测试团队后改回原名。云端问答与外部检索需要 API Key 和网络，必须在服务器上另外实测。

日常备份至少包含 `res/AcadeAgent/database.db`、`res/pdf/`、`res/layer1/`、`res/layer2/`；临时上传目录可按保留策略清理。备份 SQLite 时先停写入进程或使用 SQLite backup API；还原时保持数据库和索引来自同一快照。不要把 `.env`、生产数据库、上传论文或云端密钥推送到公开仓库。

常见故障：

| 现象 | 检查 |
|---|---|
| 登录页请求本机地址 | 确认 `config/.env.prod` 中是 `/api`，重建 `dist/`，清浏览器缓存 |
| `/health/ready` 503 | 查看数据库路径、DeepSeek Key、启动日志及本地 Chroma 初始化 |
| 上传后长期排队 | 确认 `paperagent-vector` 运行、PDF 目录可写、Worker 日志没有解析异常 |
| 翻译 503 | 执行离线模型安装脚本，确认 API 启动日志显示预热完成 |
| 混合检索为 false | 核对 BGE-M3、Reranker 文件与 `.env` 路径；基础 ONNX 仍可用 |
| 研究任务失败/重启后停滞 | 查看任务步骤错误与 API 日志；任务运行在 API 进程中，重启不会自动恢复正在执行的任务 |

本轮验证结果与未覆盖场景见 [功能验证记录](功能验证记录.md)。
