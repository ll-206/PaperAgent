# PaperAgent 快速启动说明（组员版）

克隆 GitHub 仓库后，在 `PaperAgent-main` 目录配置环境，再运行 `start_all.ps1`。
> 系统要求：Windows 10/11；使用 ChromaDB 本地向量检索，无需准备 BGE 大模型目录。

---

## 〇、压缩包应该包含什么

组长打包时，请确保包含以下内容；组员拿到后检查目录结构是否完整。

```
PaperAgent/
├─ start_all.ps1              # 一键启动脚本（双击/右键运行）
├─ 快速启动.md                # 本说明
├─ PaperQuery_Backend/        # 后端
│  ├─ main.py                 # 后端 API（端口 8001）
│  ├─ vector.py               # 向量化 Worker（处理上传文档）
│  ├─ requirement.txt         # 后端依赖清单
│  ├─ .env.example            # 配置模板；自行复制为 .env
│  └─ res/onnx_models_v5/     # 已提交的本地向量模型缓存
└─ PaperQuery_Frontend/       # 前端
   ├─ package.json
   ├─ package-lock.json
   ├─ config/                 # 环境变量（含后端地址）
   └─ src/
```

### 打包时【务必排除】以下目录/文件

| 排除项 | 原因 |
|--------|------|
| `PaperQuery_Backend/.venv/` | conda 环境绑定了绝对路径，换机器会失效，需组员本地重建 |
| `PaperQuery_Backend/.conda_pkgs/` | conda 安装缓存，约 330MB，无用 |
| `PaperQuery_Frontend/node_modules/` | 前端依赖约 600MB，组员 `npm install` 重建 |
| `**/__pycache__/`、`.pyc_cache/` | Python 编译缓存 |
| `PaperQuery_Backend/_faulthandler_dump.txt`、`tmp.txt` | 调试残留 |

`.env` 含 API Key 和密钥，不随 Git 仓库提交。每位组员需要由 `.env.example` 新建自己的 `.env`。

## 一、安装 Node.js（前端依赖）

前端用 Vite 构建，需要 Node.js 18 及以上（推荐 20/22）。

1. 下载安装：https://nodejs.org（选 LTS 版，一路默认下一步）。
2. 安装完成后，打开 **PowerShell**，验证：
   ```powershell
   node -v
   npm -v
   ```
   能打印版本号即成功。

---

## 二、安装后端 Python 环境

后端要求 **Python 3.12**。

1. 安装 Python 3.12（勾选 "Add to PATH"）：https://www.python.org/downloads/release/python-3120/

2. 在 `PaperQuery_Backend` 目录下创建虚拟环境并安装依赖：
   ```powershell
   cd PaperQuery_Backend
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install --upgrade pip
   .\.venv\Scripts\python.exe -m pip install -r req_win.txt
   ```

   > 首次安装会下载后端依赖；无需安装 FlagEmbedding 或下载 BGE-M3 / Reranker 模型。

3. 复制 `.env.example` 为 `.env`，填写自己的 LLM API Key，并将 `SECRET_KEY` 改成随机长字符串。将 `CHROMA_ONNX_CACHE_DIR` 设为 `./res/onnx_models_v5/all-MiniLM-L6-v2`，即可使用仓库自带的向量模型缓存。

4. 如需在论文阅读器中离线翻译英文选区，再运行 ` .\.venv\Scripts\python.exe scripts/install_offline_translation.py ` 下载并安装英中翻译包。安装后翻译不调用 LLM API。

首次处理论文时，ChromaDB 会使用上面指定的 ONNX 缓存目录。

---

## 三、安装前端依赖

在 `PaperQuery_Frontend` 目录执行：

```powershell
cd PaperQuery_Frontend
npm install
```

> 若安装缓慢，可先切换国内镜像：
> ```powershell
> npm config set registry https://registry.npmmirror.com
> ```

---

## 四、一键启动

双击 `start_all.ps1`，或右键选择「使用 PowerShell 运行」。

脚本会依次启动：
- 后端 API（`http://127.0.0.1:8001`）
- 向量化 Worker（`vector.py`，处理上传的文档）
- 前端页面（`http://127.0.0.1:8080`）

启动成功后，浏览器访问：

```
http://127.0.0.1:8080
在登录页点击「注册」，创建自己的账号。
```

> 首次上传论文后，向量化 Worker 需要一定时间解析与建立索引；可在 Library 页面查看处理状态。

## 五、常见问题（FAQ）

| 现象 | 原因 / 解决 |
|------|------------|
| 脚本提示「后端 Python 环境 .venv\python.exe 缺失」 | 未完成第二步，请先在 `PaperQuery_Backend` 执行 `python -m venv .venv` 并装依赖 |
| 脚本提示「前端依赖 node_modules 缺失」 | 未完成第三步，请先在 `PaperQuery_Frontend` 执行 `npm install` |
| 脚本提示「Node.js 缺失」 | 未安装 Node，见第一步 |
| 页面一直显示加载骨架（Dashboard/Library） | 后端未启动或还在加载模型，检查 8001 端口是否监听，或等待后刷新 |
| 上传文档后一直「处理中」 | 向量化 Worker 未运行，确认 `vector.py` 进程存在（可用脚本重新启动） |
| 登录失败 / Token 过期 | 确认后端 8001 正常，`.env` 中 `SECRET_KEY` 与 `ALGORITHM` 未改动 |
| 检索/问答结果为空 | 检查 ONNX 缓存目录配置、向量化 Worker 和文档索引状态 |

## 六、手动启动（不使用脚本时）

分别打开三个终端：

```powershell
# 终端 1：后端 API
cd PaperQuery_Backend
.\.venv\Scripts\python.exe main.py

# 终端 2：向量化 Worker
cd PaperQuery_Backend
.\.venv\Scripts\python.exe vector.py

# 终端 3：前端
cd PaperQuery_Frontend
npm run dev
```
